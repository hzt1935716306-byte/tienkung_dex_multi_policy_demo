# Policy Compatibility

## 结论

现有两个动作策略与行走策略不是同一个机器人控制接口。项目通过固定关节输出适配和分阶段回切，在一个 19-DOF MuJoCo 模型中实现了经过验证的单窗口演示；这属于 sim-to-sim 工程适配，不代表策略已经在统一 action space 上重新训练。

## 动作策略

- 模型：`dex_evt_liondance.xml`
- 可动关节：19
- 观测：104
- 控制频率：100 Hz
- 包含：12 个腿关节、3 个腰关节、双肩 pitch、双肘 pitch
- 固定：肩 roll/yaw、肘 yaw、手腕等关节

动作关节顺序由 ONNX metadata 读取，不依赖手写数组顺序。

## 行走策略

- 模型：`tienkung.xml`，TienKung2 Lite
- 可动关节：20
- 观测：每帧 75，10 帧历史，共 750
- 策略频率：50 Hz；MuJoCo PD 更新频率：100 Hz
- 包含：12 个腿关节、双肩 pitch/roll/yaw、双肘 pitch
- 不包含：腰关节

## 已验证结果

- 19-DOF 精确模型上，鞠躬和右手动作可完整执行并回到待机。
- 20-DOF 原生模型上，行走策略可持续站立并接受速度命令。
- 默认 19-DOF 适配模型上，静止稳定、行走启停、鞠躬、摆手及动作后恢复均通过连续测试。
- 行走 checkpoint 的零命令仍会输出周期步态，所以默认使用 `idle_motion_key` 对应动作的第 0 帧作为学习型静止稳定器。
- 29-DOF 联合模型上，即使速度命令为零，行走策略仍会因模型差异失稳，因此不作为默认入口。
- 将动作策略放入 20-DOF 行走模型时，缺少腰关节，深鞠躬无法保持平衡。

## 真正完成无缝切换的推荐路线

选定一个统一的 MuJoCo/URDF 定义，并让所有策略使用完全相同的：

1. 可动关节集合和顺序。
2. 默认关节角、action scale、PD 增益和 effort limit。
3. link mass/inertia、固定关节、碰撞体和足底几何。
4. 仿真步长、控制 decimation 和观测定义。

最直接的路线是在动作策略的 19-DOF `DEX_EVT_CFG` 上重新训练一个速度行走策略。这样两个动作 ONNX 可以保留，新的行走策略应输出同样的 19 个关节，并使用相同的 Dex EVT Liondance 资产。另一条路线是在统一的 23/29-DOF 模型上重新训练全部策略，但工作量更大。

当前 `configs/demo.json` 已使用适配方式运行同一状态机内的键盘行走、动作和动作后回走。新行走策略完成后，应移除 `WalkPolicy` 的缺失关节兼容分支，让全部输出与模型关节一一对应。
